# FruityTech Studio System Administrator Setup and Deployment Guide

This guide explains how a system administrator can set up, build, and deploy FruityTech Studio.

FruityTech Studio is a Unity desktop application. It is deployed as downloadable build artifacts (for example, ZIP packages containing `FruityTech-Studio.exe` and supporting files), not as a hosted web service.

## 1. Deployment Model

- Application type: Desktop application (Unity)
- Source location: `https://github.com/nechypak/CS362---FruityTech-Studio-`
- Unity project path inside repository: `src/FruityTech-Studio`
- Primary CI workflow: `.github/workflows/unity-ci.yaml`
- Current CI build target: `StandaloneWindows64`

There is no database server, application server, or web hosting stack required for normal deployment.

---

## 2. Required Software and Services

Install and configure the following for deployment operations:

1. Git
- Used to clone and manage source code.
- Download: `https://git-scm.com/downloads`

2. GitHub repository access
- Required for source, Actions workflows, and releases.
- Admin/maintainer permissions recommended for release management.

3. Unity licensing credentials (required by CI)
- One of the following must be configured as GitHub Actions secrets:
  - `UNITY_LICENSE`
  - or both `UNITY_EMAIL` and `UNITY_PASSWORD`

4. GitHub Actions (for automated tests/builds)
- Workflow uses:
  - `game-ci/unity-test-runner@v4`
  - `game-ci/unity-builder@v4`
- Ubuntu runners are used in current workflow.

5. Unity Editor version compatibility
- Required Unity version: `6000.3.6f1`
- Must match CI workflow configuration to avoid build/test issues.

6. Optional local build workstation software
- Unity Hub
- Unity Editor `6000.3.6f1`
- Windows build module (and/or macOS build module if you add mac builds)

## 3. Initial Admin Setup

### 3.1 Clone and Verify Repository

```bash
git clone https://github.com/nechypak/CS362---FruityTech-Studio-.git
cd CS362---FruityTech-Studio-
```

Verify these files exist:
- `.github/workflows/unity-ci.yaml`
- `src/FruityTech-Studio/ProjectSettings/ProjectVersion.txt`
- `src/FruityTech-Studio/Packages/manifest.json`

### 3.2 Configure GitHub Actions Secrets

In GitHub: `Settings -> Secrets and variables -> Actions -> New repository secret`

Add either:
- `UNITY_LICENSE`

Or add both:
- `UNITY_EMAIL`
- `UNITY_PASSWORD`

The CI workflow explicitly validates these values and fails when missing.

### 3.3 Protect Deployment Branches (Recommended)

Configure branch protections:
- Require pull request before merge to `main`
- Require status checks to pass (`test`, `build`)
- Restrict force pushes and direct commits to protected branches

## 4. Automated Build and Deployment (Recommended)

Current workflow behavior (`.github/workflows/unity-ci.yaml`):

1. Trigger conditions
- Push to `main` or `develop`
- Pull requests targeting `main`

2. Test job
- Runs Unity Edit Mode + Play Mode tests via GameCI
- Uploads test artifacts

3. Build job
- Runs after tests pass
- Builds `StandaloneWindows64`
- Uploads artifact `FruityTech-Build`

### 4.1 Admin Release Procedure Using CI Artifacts

1. Merge approved code into `main`.
2. Wait for `FruityTech CI` workflow to complete successfully.
3. Open workflow run and download artifact `FruityTech-Build`.
4. Verify artifact contents on a clean Windows machine.
5. Create a GitHub Release and upload packaged build files.
6. Publish release notes with version, platform, and known issues.

### 4.2 Artifact Packaging Standard (Recommended)

Before publishing:
- Keep all generated build files together in one folder.
- Compress into a versioned ZIP, for example:
  - `FruityTech-Studio-v1.0.0-win64.zip`
- Include:
  - executable
  - Unity data folder
  - any required runtime files generated by Unity

Do not remove generated files from the Unity build output.

## 5. Local Build Setup (Fallback / Manual Deployment)

Use this only if CI is unavailable or you need emergency manual deployment.

### 5.1 Install Build Tools

1. Install Unity Hub.
2. Install Unity Editor `6000.3.6f1`.
3. Install Windows Build Support module.
4. Clone repository and open `src/FruityTech-Studio` in Unity.

### 5.2 Build Manually

1. Open Unity project.
2. Navigate to `File -> Build Settings`.
3. Confirm `Assets/Scenes/SampleScene.unity` is in `Scenes In Build`.
4. Select `PC, Mac & Linux Standalone`, target `Windows`.
5. Click `Build` and choose output directory.
6. Zip the full output folder for distribution.

---

## 6. Deployment Validation Checklist

Run this checklist before publishing:

1. Confirm workflow success on target commit.
2. Confirm Unity version used was `6000.3.6f1`.
3. Smoke test on clean machine:
- App launches
- Audio output works
- Main scene loads and playback controls respond
4. Verify package name and version labeling.
5. Verify release notes and issue tracker links are included.

---

## 7. Security and Operations Notes

- Store Unity credentials only in GitHub Actions secrets; never commit them.
- Limit who can publish releases.
- Keep build outputs out of version control (`.gitignore` already excludes build directories).
- Rotate Unity credentials if team membership changes.

---

## 8. Ongoing Maintenance Tasks

1. Review and update workflow action versions periodically.
2. Keep Unity version pinned unless deliberately upgrading project + CI together.
3. Periodically verify release download/install flow.
4. Monitor GitHub Issues for deployment-related defects.
